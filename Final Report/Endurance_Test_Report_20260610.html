4. Analisis Error

71 errors — WS Read - Check Latest Response (432)
responseCode: Websocket I/O error  |  msg: WebSocket I/O error: Read timed out

WebSocket server tidak merespons event Check Latest dalam batas waktu timeout JMeter. Terjadi 71 kali dari 12.000 percobaan (0,59%) — intermittent, bukan sistemik. Kemungkinan disebabkan oleh lonjakan momentary pada server-side broadcast handler setelah 12.000 iterasi simultan.
Dampak: Error ini tidak memblokir alur bidding (bid tetap terkirim via 2k. WS Write - Customer Bid). Namun dari sisi user experience, client tidak mendapat konfirmasi state terbaru sebelum bid — berpotensi menyebabkan bid dengan harga stale.

7. Kesimpulan

LULUS ✓

Sistem berhasil menyelesaikan 45 menit sustained load dengan error rate 0,02% (71 dari 289.140 requests). Tidak ditemukan degradasi performa atau memory leak selama durasi test. 12.000 bid transactions berhasil dilakukan oleh 60 concurrent users.

Temuan Kritis — Endpoint Bidding Sangat Lambat di Sustained Load:
GET Current Auction State (2.633ms avg), GET Bidding Validation (2.394ms avg), dan GET Fresh Price (2.079ms avg) masing-masing melebihi threshold 2 detik — padahal di load test dan spike test endpoint yang sama hanya 33–59ms. Ini mengindikasikan server tidak memiliki caching untuk state lelang aktif, sehingga setiap request memicu query ulang ke database.
WS Check Latest Vehicle (430) — avg 1.891ms dengan P90 8.008ms. Konsisten lambat di semua test, terutama di endurance. Perlu investigasi handler WebSocket broadcast di sisi server.
Tidak Ada Degradasi: Response time awal vs akhir test tidak menunjukkan tren memburuk. GET Fresh Price justru membaik 448ms (efek cache warm-up). Sistem stabil, tidak ada memory leak terdeteksi selama 45 menit.
